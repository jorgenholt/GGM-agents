# The 2023 GGM dataset

What is in [`data_2023/`](../data_2023/), what each file and scenario does, and what we learned from
reading it.

*Written 2026-09-30 from a read-through of every workbook, checked against the loading code in
`ggm/GlobalGasModel/src/SubModules/data_load.jl`. Counts are exact; anything interpreted rather than
read off the files is marked as a guess.*

> **Provenance.** Received from the GGM authors on 2026-09-30 and committed with their permission.
> **Private repo only** — never copy it into the `ggm/` submodule (a fork of a public repo) or
> anywhere public. The submodule's own `ggm/data_2023/` stays empty.

---

## 1. What the files are

11 workbooks, all in the format the Julia loader expects — every one of the 18 sheets it reads is
present with the column names it looks for.

| Workbook | Variants | What it holds | Changes between scenarios? |
|---|---|---|---|
| `general_data_<X>` | `NENO`, `SQAB`, `EUSD` | The world: nodes, pipelines, LNG terminals, storage, shipping distances, cost defaults, market power, sales restrictions | Only in two places — see §3 |
| `projected_data_<Y>` | `FFF`, `MCA`, `NCA`, `TZE` | Future production and consumption per node and year, plus sector and season shares | Only the reference quantities |
| `calibrated_data_<Y>` | `FFF`, `MCA`, `NCA`, `TZE` | The tuned values: production costs, capacity slack, prices | Future-year factors only — see §5 |

A run is named `<Y>_<X>`, e.g. `FFF_NENO`, so **12 combinations** are possible. `STEPS_NENO` — the
example written in `ggm_2023.jl` — is not one of them.

`ggm_2023.jl` hardcodes the path `ggm/data_2023/`. To run against this folder without editing GGM
source, call `get_GGM_inputs(scen, Years; data_file_path = ...)` from our own script. Not needed
this semester.

## 2. The network

| | Count | Notes |
|---|---|---|
| Nodes, total | 239 | 136 geographic + 37 liquefaction + 66 regasification |
| Countries | 125 | Large countries split into several nodes, as in 2019 |
| Pipelines | 267 | Capacity per 5-year period, length, offshore share, expansion limits |
| Liquefaction / regasification arcs | 37 / 66 | Connect geographic nodes to their LNG terminal nodes |
| Shipping routes | 37 × 66 = 2,442 | **Generated by the code**, every export port to every import port — not listed in the Arcs sheet |
| Storage rows | 363 | 121 nodes × 3 types (seasonal, peak, LNG) |
| Traders with market power | 11 | |
| Seasons / resources / demand sectors | 3 / 3 / 4 | L, H, P · R1–R3 · residential, industry, power, transport |
| Model horizon | 2020–2060 | Some sheets run to 2075; the extra years are ignored |

Liquefaction and regasification nodes are prefixed `L` and `R` (e.g. `LQAT`, `RDEU_W`). European LNG
terminal nodes carry the region label `EUR`, separate from `EU` and `ROE`, which are used for the
geographic nodes. Every geographic node is flagged for consumption, production and storage; whether it
actually produces or consumes anything is decided by its numbers, not the flags.

## 3. The three general variants

A cell-by-cell comparison shows each differs from `NENO` in exactly one sheet:

| Variant | Differs from NENO in | What it does |
|---|---|---|
| `NENO` | — | No Russian or Belarusian pipeline gas to Europe: those pipelines are at zero capacity |
| `SQAB` | Arcs only (8 pipelines) | Restores them from 2025: +178 bcm/yr into Poland, Ukraine, the Baltics and Finland |
| `EUSD` | Sales Restrictions only | NENO plus a **zero sales limit for Russia in 38 European nodes** (28 EU, 10 other European), 2025–2060 — covers LNG as well as pipeline gas |

So `NENO` looks like the baseline, and the other two are the "Russia to Europe" dials turned one way
or the other. *Guess, unconfirmed:* SQAB may stand for "status quo ante bellum".

This is exactly the kind of scenario used as the worked example in
[`how-it-would-work.md`](how-it-would-work.md) — the 2023 dataset already contains it.

## 4. The four scenarios

All four share the same 2020 starting point and differ only in their reference quantities and
calibration. Global reference totals, bcm/yr:

| Scenario | 2020 | 2030 | 2040 | 2050 | 2060 |
|---|---|---|---|---|---|
| `NCA` | 3,847 | 4,335 | 4,320 | 4,304 | 4,304 |
| `MCA` | 3,847 | 3,865 | 3,256 | 2,648 | 2,648 |
| `FFF` | 3,847 | 3,913 | 1,957 | **0** | **0** |
| `TZE` | 3,847 | 3,263 | 1,631 | **0** | **0** |

(Consumption shown; production follows the same shape, within about 3 % of it.)

*Guesses, unconfirmed:* NCA and MCA read like "no" and "moderate climate action"; FFF and TZE are two
routes to zero gas use by 2050 — FFF holds up until 2030 and then drops fast, TZE declines from the
start. In MCA, EU consumption falls from 395 to 46 bcm/yr by 2050.

Shared by all four: the same sector shares, the same season shares, and the same price elasticities
(residential −0.2, industry −0.4, power −0.75, transport −0.25).

**Zero-demand years.** In FFF and TZE from 2050, reference consumption is zero. The demand-curve slope
divides by it ([data_load.jl:176](../ggm/GlobalGasModel/src/SubModules/data_load.jl#L176)), producing
infinities and NaNs, which the loader's general safety net replaces (∞ → 10,000, NaN → 0) with a
logged warning ([data_load.jl:337](../ggm/GlobalGasModel/src/SubModules/data_load.jl#L337)). The
result is effectively "no demand", but reached through a fallback rather than by design.

## 5. The calibration — what actually gets tuned

This is the most useful section for the thesis. It puts numbers on the calibration burden the 2019
documentation only describes in words.

**What is tuned in one scenario (NCA)** — values that differ from their neutral setting:

| What | Tuned | Of |
|---|---|---|
| Production base cost, one per node | 136 | 136 |
| Production capacity slack factors (per node and year) | 1,223 | 1,224 |
| Production cost year factors | 109 | 1,224 |
| Production cost multipliers `c(R)` | 3 | 408 |
| Base price, one per node | 136 | 136 |
| Seasonal price factors (L/H/P) | 292 | 408 |
| Price year factors | 682 | 1,224 |
| Arc usage / investment cost factors | 52 | 740 |
| Storage calibration factors | 0 | 726 |
| **Total** | **≈ 2,630** | |

**What changes from one scenario to the next.** Compared with NCA, the other three scenarios change
between **≈ 1,700 and 2,050 calibrated values** each — all of them future-year factors (production
cost, capacity slack, price). Base costs, base prices and seasonal factors stay the same. This
matches the documented practice of calibrating the base year once and then re-tuning future years
per scenario.

**Levers that exist but are switched off:**

- **Global losses** are 0 in every year of every scenario. The reconciliation the 2019 documentation
  describes is not used.
- **Storage calibration factors** are all 1.
- **Market power never fades.** The code takes the larger of `export × minimum ratio` and
  `export × 0.7^periods` ([data_load.jl:157](../ggm/GlobalGasModel/src/SubModules/data_load.jl#L157)).
  With the ratio set to 1 for every trader, the first always wins, so the 0.7 decay does nothing. In
  2019 the ratio was 0.5.

**Market power values** sit in the general workbook, so they are the same in all four scenarios.
Export market power: Russia 0.5, Qatar 0.3, Algeria 0.3, USA 0.2; Iran, Saudi Arabia, China, India,
Venezuela, Turkey and Mexico 1.0 (full Cournot). No trader has domestic market power. Russia has 0.75
in Iraq; Iran has 1.0 in Belarus.

**Production cost curves.** The multipliers are `q(R1) = 1`, `q(R2) = 5`, `q(R3) = 8`, with `c(R)`
mostly 1 — exactly the values in the 2019 documentation's worked example. Capacity shares are
50 / 46 / 4 %, also as in 2019. Slack is 0–2.4 %, below the 3–5 % the documentation recommends.

## 6. The size of each input layer

Checking the four-layer view in [`workflow-task-inventory.md`](workflow-task-inventory.md) against
real data. Counts are numeric cells in one scenario combination:

| Layer | Values | What |
|---|---|---|
| 1. Physical facts | ≈ 15,200 | Pipeline capacities and lengths, storage capacities, shipping distances |
| 2. Projections | ≈ 9,400 | Reference quantities (2,448 per scenario), sector and season shares |
| 3. Literature parameters | 26 | The Other Assumptions sheet plus four elasticities |
| 4. Calibrated | ≈ 7,050 | ≈ 2,630 of them actually tuned (§5) |
| Scenario settings | ≈ 1,900 | Expansion limits (1,836), market power (48), sales restrictions |

The four layers hold up, with one addition: **scenario settings** — expansion limits, market power
and sales restrictions — are neither collected facts nor calibration. They are choices about what
world is being modelled, and they belong with scenario design.

## 7. Oddities worth knowing

- **`Minium Market Power Ratio`** is misspelled in the sheet — and the code expects the misspelling.
  Correcting it breaks the run.
- **Storage operating costs are labelled `OPEX (USD/kcm)`** but used as EUR with no conversion
  ([data_load.jl:135](../ggm/GlobalGasModel/src/SubModules/data_load.jl#L135)). Either the label is
  stale or storage costs are off by the exchange rate.
- **`DistCutOff`** (15,000 sea miles) is in the Other Assumptions sheet but the code never reads it,
  so every shipping route exists.
- **Three cost defaults sit outside the low–high range written next to them** in the same sheet:
  pipeline investment 100,000 (range 27,375–73,000), liquefaction loss 0.08 (0.10–0.14), and shipping
  loss 0.01 per 1,000 sea miles (0.0025–0.004). The shipping loss is three times the 2019 value.
- **Cost defaults changed since 2019:** operating fees are higher across the board — liquefaction 30
  (was 20), pipeline 20 per 1,000 km (was 7), regasification 20 (was 10), shipping 15 (was 8) EUR/kcm.
