\section{The workflow around the model}

The documentation describes the model and its data, but not the order in which the work is done.
Reading it together with the code and the 2023 data suggests six steps, which Chapter 5 follows:

\begin{enumerate}
  \item \textbf{Get source data:} find the current editions of statistics and outlooks, and extract the relevant figures.
  \item \textbf{Prepare the data:} convert units, map figures to nodes, split country totals and fill in missing years.
  \item \textbf{Set up the scenario:} choose the outlook and the network variant, and set expansion limits, market power and sales restrictions to match the scenario.
  \item \textbf{Calibrate:} adjust costs, capacities, prices and market power until the model reproduces the reference values.
  \item \textbf{Run the model:} build and solve the optimisation problem and write out the results.
  \item \textbf{Read the results:} check the results for consistency and interpret them as findings.
\end{enumerate}

The steps are not strictly sequential.
Calibration requires repeated runs, a scenario that cannot be calibrated may send the analyst back to the data, and implausible results may reveal a problem in any earlier step.
The work is also unevenly documented.
Data sources and processing rules are described in detail, calibration is described by its principles and a few worked examples, and scenario design and the interpretation of results are not described at all.

Some checks are already automated.
When loading the data, the code reports any node whose projected exports or imports exceed the transport capacity available to it.
The model produces tables of production, flows, investments and prices; the 2019 version also produced reports comparing model outcomes with the reference values \citep[p.~26]{egging2019global}, but the public Julia version does not.
